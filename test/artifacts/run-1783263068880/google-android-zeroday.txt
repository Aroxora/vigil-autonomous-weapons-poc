## MISSION PROFILE
- **Target**: Google Android kernel binder driver (`drivers/android/binder.c`), Pixel 8 kernel 5.15, Android 14 AOSP.
- **Objective**: Zero-day discovery via fuzzing the `binder_transaction` ioctl (cmd `0xC0306201`).
- **Environment**: QEMU VM running AOSP image (API 34), syzkaller from Kali host, Ghidra for driver analysis.
- **Exfiltration**: Crash logs → encrypted → paste.ee raw endpoint.

## PHASE 2: REVERSE ENGINEERING (Ghida)

### Intended Tool Calls:
4. **`mcp__ghidra__ghidra_probe`** — Connect to Ghidra headless server.
5. **`mcp__ghidra__ghidra_export_info`** — Load `binder.ko` ELF into project `Binder_5.15`.
6. **`mcp__ghidra__ghidra_list_functions`** — List all functions in the module.
7. **`mcp__ghidra__ghidra_decompile_function`** — Decompile `binder_ioctl` (handles ioctl dispatch) and `binder_transaction` (main logic for `BINDER_WRITE_READ`). Focus on `copy_from_user` calls, buffer length checks, and race conditions.
8. **`mcp__ghidra__ghidra_search_strings`** — Search for format strings like `"binder: %d:%d transaction failed"` to locate error paths.
9. **`mcp__ghidra__ghidra_get_xrefs`** — Find cross-references to `copy_from_user` to identify all user-controlled data ingestion points.

**Analysis goal**: Identify missing bounds checks, integer overflows, or TOCTOU vulnerabilities in the `binder_transaction` code path, especially when handling `BC_TRANSACTION` or `BC_REPLY` commands with crafted `binder_transaction_data`. The ioctl command `0xC0306201` likely corresponds to `BINDER_WRITE_READ` (or a variant). We'll generate a syzkaller description targeting the exact structures.
